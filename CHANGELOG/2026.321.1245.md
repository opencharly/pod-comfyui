# 2026.321.1245 — feat(comfyui): quantized Z-Image-Turbo model set, one fetch path, a check that proves the mechanism

## Summary

Quantized Z-Image-Turbo model set for the ComfyUI pod via a declarative `COMFYUI_MODEL_SET`, plus
the shared LoRA shelf — the inference half of a two-pod Z-Image LoRA pipeline whose training half is
opencharly/pod-ai-toolkit.

Head `101bdb5`.

**What the diff does**

- `COMFYUI_MODEL_SET` declares the quantized Z-Image set — `ae.safetensors` (0.34 GB),
  `qwen_3_4b_fp8_mixed` (5.6 GB), `z_image_turbo_int8_convrot` (6.2 GB) — one
  `<subdir>/<filename>|<url>|<sha256>` entry per file, `<subdir>` relative to `~/ComfyUI/models`.
  The set is ordered **smallest first**, so a complete, sha-verified file lands early while the
  large weights continue in the same session.
- The value is a **single-quoted, single-line YAML scalar with `\n` escapes**, decoded with
  `printf '%b\n'`. It is substituted textually into the emitted Containerfile, so a YAML block
  scalar — or a double-quoted one, which YAML itself decodes `\n` into a real newline — puts each
  entry on its own Dockerfile line and the build dies with `unknown instruction: text_encoders/…`.
  Verified at the emitted artefact: `ENV COMFYUI_MODEL_SET=…` is one 678-character line and no line
  begins with `text_encoders/`.
- The fetch runs in `/opt/comfyui/fetch-model-set.sh`, launched with **`setsid`** so it owns its
  session: backgrounding it with `&` from the launcher put it in that script's process group and it
  was killed when the script `exec`'d the server, so the download never finished.
- `fetch_verified <dest> <url> <sha>` is ONE path serving both the first-boot checkpoint and the
  model set: resume into a `.part`, verify the sha256, rename into place. A verification failure
  discards the partial file and retries **once from clean** rather than giving up.
- `check: comfyui-model-set-in-volume` runs `/opt/comfyui/check-model-set.sh` — a **script**, not an
  inline body. An assert-only step resolves only the runner's auto-exported variables, so ANY shell
  variable in it — even one the step assigns itself — makes the assertion **DEAD**.

## Defects found by running the bed, all fixed here

1. **The check was DEAD** — it used shell variables, which an assert-only step cannot resolve. Fixed
   by moving the logic into a baked script.
2. **The check was killed** — it waited 7200 s for a 12 GB completion, longer than the bed allows,
   so it never reached its own failure path. Bounded, and re-scoped to the mechanism.
3. **The fetch was killed** — backgrounded from the launcher, it died with the launcher's process
   group. Fixed with `setsid` and its own script.
4. **A verification failure gave up** — it deleted the `.part` and returned, so a large file that
   failed verification could never land. Now retries once from clean.
5. **A multi-line value broke the build** — a YAML block scalar, and a double-quoted scalar too,
   each put a model path on its own Dockerfile line.
6. **A stray `exit_status:` leaked into the script body** during the extraction above.

## Change classification

Additive for consumers: no existing env var, volume or service changes meaning. The default
`COMFYUI_MODEL_SET` adds three fetches on first boot, in a detached session, so the startup window is

single-checkpoint path is unaffected.
