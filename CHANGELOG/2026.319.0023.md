```
TypeError: init() got an unexpected keyword argument 'simple_vram_headroom'
```

Every ComfyUI-derived pin is now the version the **pinned tag's own `requirements.txt` names**
(`comfyui-frontend-package==1.58.5`, `comfyui-workflow-templates==0.11.107`, `comfyui-embedded-docs==0.5.16`,
`comfy-kitchen==0.2.41`, `comfy-aimdo==0.6.0`, `simpleeval>=1.0.0`, `blake3`), `torch` is pinned to the CUDA
build proven on this host, and the lock is re-solved.

**2. Unpinned clone.** The plan cloned ComfyUI at `--depth 1` on `main` into `~/ComfyUI`, so the image's
content depended on the build day. It now clones the pinned tag (`COMFYUI_REF: v0.45.3`) into `/opt/comfyui`
and records it in `.charly-ref`, which a `check:` asserts.

**3. App/state collision, a dead Manager clone, and undeclared inputs.** The application and all state shared
`~/ComfyUI` (the volume path), so a volume populated from an older image shadowed the app forever; the plan
cloned `ltdrdata/ComfyUI-Manager` although current ComfyUI ships `--enable-manager`; and the start script
hard-required a checkpoint URL and sha256 that the candy never declared. Now: `--base-directory` into the
volume, `--enable-manager`, the start script seeds the **full** state tree (`custom_nodes/` included — its
absence is a hard start failure: `FileNotFoundError: /home/user/ComfyUI/custom_nodes`, measured), an **absence**
check pins the legacy Manager path gone, and `COMFYUI_MODEL_URL`/`COMFYUI_MODEL_SHA256`/`COMFYUI_MODEL` are
declared in `env:` with the proven artifact as the default plus `env_accept` overrides.
