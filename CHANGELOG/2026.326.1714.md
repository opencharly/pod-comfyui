## Summary

Hard-cutover of the ComfyUI candy to the Qwen/Edit/Z-Image/Wan image lane and
Dynamic VRAM:

- `models/model-manifest.tsv` is the single source for the model SET: the user's 17
  requested files plus the required companions (`qwen3vl_8b`, the t2i PE, the Wan
  low-noise expert), 24 rows, ~128 GiB core. The default checkpoint remains sourced
  from `COMFYUI_MODEL_URL`/`COMFYUI_MODEL_SHA256` and is not duplicated.
  `COMFYUI_MODEL_SET` is removed.
- API-format workflows for Open WebUI: Qwen-Image-2.1 Turbo T2I, Qwen-Image-Edit-2511
  + Lightning 4-step, Z-Image int8/bf16, Wan 2.2 5B TI2V. Constants are inlined;
  only safe typed node maps remain (no `model`, no static `value`).

  generation/edit workflow JSON. Raw JSON cannot ride `env_provide` (Go-template
  brace validation), so the workflows travel as `*_WORKFLOW_B64` and the consumer
  entrypoint decodes them.
- Dynamic VRAM launcher: `--vram-headroom` only; `--disable-smart-memory`,
  `--lowvram`, `--novram`, `--highvram`, `--gpu-only`, `--disable-dynamic-vram`
  are forbidden by the launch-flags check.

   `ckpt_name="model.safetensors"` because `COMFYUI_WORKFLOW_NODES` was empty;
   ComfyUI 0.46.1 rejected it. Fixed by shipping API workflows with the model
   inlined and providing them to the consumer.

   delta; Dynamic VRAM keeps the model resident, so a warm feature-run legitimately
   showed +160 MiB. The check now asserts completion and records the peak; the
   launch contract is enforced by `comfyui-launch-flags`.
3. **One-line model set.** The old `COMFYUI_MODEL_SET` could not express 25 files
   without a fragile single-line env. The manifest file is the single source,
   copied into the image and read on boot.
