# 2026.319.0108 — fix(comfyui): the plan checks read the RUNTIME env, and the server probe waits

## Summary

A bed run (`check-cachyos-comfyui-pod` run `2026.319.0028`, image built from this candy's `v2026.319.0023`) found
that **two of this candy's own checks never ran**:

```
SKIP  check the image records the ComfyUI release tag it was built from  [comfyui-pinned-ref]
        unresolved variables: COMFYUI_REF
SKIP  check the model checkpoint lives in the STATE volume, not in the image  [comfyui-model-in-volume]
        unresolved variables: COMFYUI_MODEL
```

**Why that is the worst kind of green.** A braced reference is expanded by the plan runner against the TASK env,
and the step **SKIPS** when it cannot resolve it. `env:` declarations reach the IMAGE, not the check context — so
both checks were decorative. `comfyui-model-in-volume` is the single check that would catch a broken first boot;
it has been reporting nothing since it was written. Refs #12.

**Fixes:**

| check | fix |
|---|---|
| `comfyui-pinned-ref` | no interpolation at all — assert the FILE is version-shaped (`^v<digits>.<digits>`). The BED owns the tag value and asserts it against the server's own API. |
| `comfyui-model-in-volume` | BARE `$COMFYUI_MODEL` / `$HOME`, which pass through to the shell and read the CONTAINER's environment at run time. The `-n` guard matters: unset, the path would be the `checkpoints/` **directory**, and `test -s` on a directory is **true**. |
| `comfyui-system-stats` | `eventually: 5m` + `retry_interval: 10s`. On a fresh volume the server is still fetching a 2 GB checkpoint, and a single probe gets `connection reset by peer` — measured, while a retrying sibling check passed 2m53s later. |

### The one red step in that bed run, root-caused and accounted for

`[image-build] PASS 1m22s · [check-image] PASS 30s · [deploy-add] [config] [start] [wait-ready] PASS
[check-live]  PASS 3m19s
83 steps: 74 passed, 0 failed, 9 skipped` — the failure is **not** in this PR's three checks, but it is this
PR's gate, so it is answered here rather than waved through (R1).

```
FAIL  check a REAL generation round trip …  [comfyui-generation-roundtrip]
        exit=1, want 0 (stderr: curl: (22) The requested URL returned error: 400)
```

**Root cause, mechanism:** the distro bed's workflow is a **single-quoted** shell string, so the earlier
`"$COMFYUI_MODEL"` sat *inside* the quotes and never expanded. ComfyUI received a checkpoint literally named
`$COMFYUI_MODEL` and answered `400`. The check was not lying — it was reporting a real malformed request, which is
exactly what a check should do once it stops skipping.

**The fix (consumer side, `distro-cachyos` commit `2cac721`)** breaks the quoting where the value crosses
(`"'"$COMFYUI_MODEL"'"`), and here is the proof, reproduced from the same `wf=` line the step runs:

```console
$ bash prove-wf.sh          # COMFYUI_MODEL=v1-5-pruned-emaonly-fp16.safetensors; the wf= line from charly.yml
JSON valid; ckpt_name = v1-5-pruned-emaonly-fp16.safetensors
nodes: ['3', '4', '5', '6', '7', '8', '9']
```

**The missed control (R1, named):** I verified that the check *ran* — it stopped skipping, and its exit code was
visible — and never inspected the **payload it emitted**. "The check executed" and "the check sent the right bytes"
are different claims, and only the first was in my pre-push audit. Added: when a check's failure quotes an HTTP
status, reproduce the request body locally before theorising.
