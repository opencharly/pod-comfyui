# 2026.324.1925 — fix(comfyui): pin HOME for a bound deployment

## Summary

Pins `HOME: /home/user` in the ComfyUI candy so a **bound** deployment uses its mounted
state volume and the shared models instead of silently re-fetching everything under `/root`.

**Why it is needed.** A host-owned bind makes charly run the container as root under its keep-id
mapping, where the runtime `HOME` is `/root` — while the candy's state volume and the nested
models bind are mounted at `/home/user/ComfyUI`. The start script computes `BASE=${HOME}/ComfyUI`,
so without the pin it ignores both mounts and downloads the model set into the container layer.

**Measured (R1).** `check-comfyui-openwebui-pair` run `2026.324.1540`: the member had
`HOME=/root` and downloaded SD1.5 into `/root/ComfyUI/models` while the shared checkpoint was
already present in the bind at `/home/user/ComfyUI/models`. With the pin, the member resolves
`BASE=/home/user/ComfyUI` and uses the bind. The pair-bed claim is deliberately **not** made here:
that bed still fails at its Open WebUI auth roundtrip (`jwt=400 key=401`), unrelated to this pin;
the explicit control below is the proof.
