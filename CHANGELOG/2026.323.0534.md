## Summary

`charly-comfyui` kept a 2 GB checkpoint in VRAM for as long as the server ran: **10,954 MiB**
resident with `/queue` empty. On a 16,376 MiB card that is the difference between "a ComfyUI

That is the flag, and it is the only one of the three in play that changes behaviour here.

**`--enable-dynamic-vram` is deliberately NOT re-added.** It *permits* dynamic loading; it does
not offload, and on this launch it is already on. `enables_dynamic_vram()` answers true unless
one of five conflicting flags is passed:

```console
$ sed -n '336,339p' comfy/cli_args.py

        return True
    return not args.disable_dynamic_vram and not args.highvram and not args.gpu_only and not args.novram and not args.cpu

$ sed -n '291p' main.py

```

The second clause of that `if` is already true for an NVIDIA device with no conflicting flag, so
passing the flag by hand enters the same branch and changes nothing. Adding it for symmetry
would be a flag that says what the recipe already means.

**The 1 GiB headroom floor is NOT the mechanism.** `--vram-headroom` sets the margin DynamicVRAM
keeps free; it does not decide what is loaded:

```console
$ grep -n 'vram-headroom' comfy/cli_args.py
177:parser.add_argument("--vram-headroom", type=float, default=0, help="Set the amount of vram in GB for DynamicVRAM to maintain as extra headroom above default. ComfyUI will try and keep this much VRAM completely free and unused, even counting VRAM from other apps.")
```

At the measured peak the card still had 10,396 MiB unused (16,376 − 5,980), so a 1 GiB floor was
satisfied the whole time and never constrained anything. It stays, because it is a real policy
knob for a GPU shared with other work; it is not a memory bound, and the skill now says so.

**What the earlier round measured, and why it could not see this.** #27 dropped these flags on
the strength of a reading taken with the server idle and nothing loaded — "idle VRAM was
byte-identical at 368 MiB patched and unpatched". That is exactly what the flag must look like
before anything has been loaded: `--disable-smart-memory` acts at model load and at prompt
completion, so a comparison made before either is identical **by construction**. The missed
control is the state, not the flag list: the effect of a load/unload flag cannot be measured in
the one state where it has nothing to act on.

**What the diff carries, so every line has an owner:**

- `charly.yml`, the launcher: `--disable-smart-memory` in the `exec:` argv, plus the comment
  above it that names `execution.py` and `free_memory()` instead of reasoning from the flag's name.
- `charly.yml`, a new baked script `/opt/comfyui/check-vram-offload.sh` (a `write:` step) — the
  runtime check below, including its per-run nonce (see How tested).
- `charly.yml`, a new `check:` step `comfyui-vram-offload`, `context: [runtime]`, which runs that
  script.
- `.agents/skills/comfyui/SKILL.md`: a VRAM section (the table, the process footprint, what
  `COMFYUI_VRAM_HEADROOM` is not) and one paragraph naming the check.

**The check that has teeth.** `comfyui-vram-offload` runs one 512×512 / 8-step prompt and
asserts a DELTA on the card: the used-VRAM reading rises by at least 1 GiB while the prompt runs
— the 2034 MiB checkpoint really went onto the device — and then settles back within 768 MiB of
the pre-prompt reading. It asserts a delta and never an absolute footprint, because `nvidia-smi`
reports the whole device: another container's models are in the same number, and only the delta
is attributable to this deployment. The logic lives in a baked script because an assert-only
step cannot carry shell variables at all (measured on a bed run).

The runner records a check's exit status, not its stdout, so the passing arm's per-phase
`before/peak/settled` numbers are not in its `summary.yml`; the failing arm's numbers ARE in its
reason, because a failing check prints what it measured.

**A defect this bed caught and this head fixes.** The first run of ARM 1 failed its own check on
the `feature-run` phase: `the prompt did not put the checkpoint on the card (peak rose 0 MiB,
expected >= 1024); the check would prove nothing`. The check was wrong, not the flag — ComfyUI
keys its execution cache on the prompt graph, so the SECOND identical prompt is answered from
cache, nothing loads, and the load half of the assertion refused to certify a run that proved
nothing. The prompt's seed and output prefix now carry `$(date +%s)`, so every run is a distinct
graph and a cache miss. The failing summary is retained at
`.check/check-comfyui-pod/2026.323.0448/summary.yml`.
