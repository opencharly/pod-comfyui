# 2026.331.1132 — fix(check): judge only the CURRENT fetch run, not the whole appended log

## Summary

`check-model-set.sh` — the `comfyui-model-set-in-volume` witness — failed whenever `FAILED|SHA MISMATCH`
appeared **anywhere** in `model-set-fetch.log`. That log is **appended across container restarts** (the
fetch script writes one `=== fetch start <ts> ===` marker per run), so a failure from an old run kept the
check red forever.

Measured on the running `comfyui-cdi` deploy (`opencharly/pod-comfyui#61`):

```
$ grep -c '=== fetch start' "$HOME/ComfyUI/model-set-fetch.log"
14                                   # 14 appended runs
$ grep -n 'SHA MISMATCH' "$HOME/ComfyUI/model-set-fetch.log"
93:SHA MISMATCH …/text_encoders/qwen3vl_8b_int8_convrot.safetensors   # an OLD run's line
$ tail of the last run
  === fetch done 2026-11-27T09:33:00Z ===
$ ls "$HOME/ComfyUI/model-set.done"   # the set completed
$ sha256sum …/qwen3vl_8b_int8_convrot.safetensors
8bfd0f6e12abf2d2d697ecc888e5e90b0d6741d6708f05799f53afa560452e8f   # == the manifest row
```

Two consecutive `check live comfyui-cdi` runs were red on that same historical line.

The fix scopes the verdict to the segment **after the newest marker** (and to the whole file only when
there is no marker at all).

### Spike

| Candidate | Run + result |
|---|---|
| A — truncate the log at the start of every fetch run | **not spiked, and not claimed to work**: rejected on design grounds alone — it would discard the record of a previous run's failure, which is the evidence an operator needs, and the log's `=== fetch start ===` markers exist precisely to delimit runs. Only B was measured |
| **B — scope the CHECK to the newest run's segment** (winner) | the pasted old-vs-new run above: rc=1 against rc=0 on the same real log, and the other eleven log readers (`grep -c`, the failure cat) keep working |
